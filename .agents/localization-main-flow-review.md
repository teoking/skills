# 主流程本地化审查记录

## 范围与基线

本轮覆盖 `ask-matt`「想法到交付」主流程：12 个直接技能（含无工作目录时的 `grill-me` 入口）、4 个共享依赖、首次配置和路由，共 18 项。16 项新增中文化；`grilling` 和 `writing-for-agents` 沿用中文版本并复核、修正。同步对应说明页、界面元数据、配套参考、首页和分桶索引，以及 [LOCALIZATION.md](../LOCALIZATION.md)。

- 主流程内容基线：`097bb98d25501adc45f0dc0fb8ce6f32b3371d44`，包版本 `1.3.1`。
- 两项既有中文技能的英文对照基线：`03866313a2a4352408ab508e5925f828ae106b0d`。
- 本轮不升级上游功能、不新增或重命名技能、不修改插件发布集合、安装来源或全局安装，也不自行提交或推送。
- 新增的默认简体中文交互是用户授权的 fork 偏好，不是上游原文要求；用户指定其他语言时遵从用户。
- `triage`、`wayfinder`、`research`、`wizard`、`teach`、`to-questionnaire` 和 `wait-what` 的正文不在本轮范围。此前架构技能审查中尚未应用的建议也未顺带修改。

| 逻辑任务组 | 技能 | 主要边界 |

| 审查、PR 与复盘 | `code-review`、`pr`、`retro` | 独立审查轴、最小可视化、证据、合并风险、环境改进 |

实际分为 9 个不重叠的文件编辑批次：需求入口与领域建模、交接与原型、规格说明与工单、实现与 TDD、审查与 PR 及复盘、深模块参考、首次配置、路由、两项既有中文技能。各批次分别完成本地化，再由独立上下文的只读 agent 全文对照基线审查。独立指上下文与只读权限独立，不代表人工审查或不同模型交叉验证。

审查只报告问题，修正另行执行。低于 8 分的项目修正后重新审查；静态检查发现关键问题时同样不能放行。不执行技能中描述的业务流程。

## 评分规则

评分依据为 `tech-doc-style-chinese` 及其术语排版、受控中文技术写作参考。这份 10 分制是本任务按规则优先级建立的量表，不是该技能自带量表，也不表示获得任何语言标准认证。

| 维度 | 满分 | 核对内容 |
| --- | ---: | --- |
| 事实与语义保真 | 4 | 事实、条件、例外、否定范围、步骤顺序、要求强度、安全信息 |
| 标识与调用机制 | 2 | 技能名、调用策略、依赖调用、CLI、代码、路径、配置和模板字段 |
| 术语一致 | 1.5 | 首选术语、首次英文说明、技能与说明页一致 |
| 结构与可执行性 | 1.5 | 信息层级、动作对象、条件顺序、页面框架、可扫读性 |
| 语气与排版 | 1 | 克制准确、中文标点、直角引号、中西文留白、段落格式 |

关键事实、前置条件、限制、调用策略或机器字段存在错误时，总分封顶 7.9，即使分项合计更高。通过要求为总分至少 8 且无关键问题。说明页如与同一基线的 `SKILL.md` 不一致，以技能正文作为行为依据，明确记录源文一致性修正，不把正文未保证的结果继续写成承诺。

分数是审查发现的汇总，不是客观测量或运行可靠性指标。满分仅表示该次全文对照没有发现可定位的扣分项，不保证没有未知问题。多轮评审可能发现前轮遗漏；最终采用最后一轮完整审查，而不选择最高分。

## 审查与修正

### prototype：补回默认范围与数据库例外

首轮说明页继承了英文页面的过度概括，将「默认不持久化」写成无条件「不做持久化」，并将两种原型都描述为无例外使用内存。与 `SKILL.md` 允许临时数据库或原型本地文件的条件冲突，首轮分项合计为 9.5，总分封顶 7.9。

已在 [prototype 说明页](../docs/engineering/prototype.md) 补回默认范围及数据库例外，保留不使用生产数据、可抛弃原型、提取答案及保留原型分支的边界。复审为 10.0，PASS。

### to-tickets：分开归属与阻塞，限定跟踪器模式

首轮为 9.7。说明页将子工单关系混入阻塞关系的表示方式，属于基线遗留的一致性问题。已区分父子归属与执行阻塞，补全原生关系不可用时的 `Blocked by` 回退，并明确完全线性的依赖链才按自上而下执行。

在修正后的中间版本中，建立父子关系的句子遗漏了「真实工单跟踪器模式」条件，会被理解为本地 Markdown 模式也能执行该操作。该轮分项合计为 9.2，总分封顶 7.9。已在 [to-tickets 说明页](../docs/engineering/to-tickets.md) 限定适用模式，没有为本地模板新增父子关系操作。再次复审为 10.0，PASS。

### code-review：显式记录源文排除条件冲突

英文说明页写的是 `Both axes skip anything your linter already enforces.`，但同一基线的技能正文只在 Standards 提示词中明确规定跳过工具已检查的事项，Spec 提示词没有对应要求。中文说明页按正文写为 Standards 跳过，却未披露这一源文冲突。首轮为 9.8；后续完整复审发现此问题，分项合计为 9.6，总分封顶 7.9。

本轮按技能正文作为行为依据，在 [code-review 说明页](../docs/engineering/code-review.md) 显式说明基线页面与提示词的差异，不承诺 Spec 也会跳过。这是源文一致性修正，不是等义翻译。未向 Spec 提示词追加排除规则，也未改变实际审查流程。修正后完整复审为 10.0，PASS。

### 其他已完成的修正

- `domain-modeling`：补正通用辅助代码模式的术语、`triage` 的领域语境，以及一天内构建时的直接建议力度。
- `writing-for-agents`：补正 `deterministic` 的确定性含义、上下文指针、完成边界、否定与无效指令；恢复英文基线已有但初始中文遗漏的 FAQ 与字典链接。
- `grilling`：补回持续深入检验的要求力度和既有 FAQ，保留每轮整个前沿、事实调查、用户决策及最后确认。
- `code-review`、`pr`：将可选处理方式和风险阅读分支改为列表，保留全部条件与更新风险。
- `codebase-design`：区分当前并行子代理要求与原 docs 中提及 `Agent tool` 的旧问题说明，不宣称宿主已适配。
- `ask-matt`：使用本地配套参考链接，补齐说明页的路由链接，保持「先读取，再推荐，不执行」的边界。

其他基线说明页与正文的一致性修正包括：`/clear` 不生成摘要；`implement` 遇到歧义可以询问；集成分支同步不保证无冲突或快进合并；PR 就绪不等于工单关闭；TDD 重构留在审查阶段；setup 的标签创建和 monorepo 问题均有条件。这些修正没有变成新的技能能力。
